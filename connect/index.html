hosted.py
import asyncio, json
from mcp import ClientSession
from mcp.client.streamable_http import streamablehttp_client

URL = "https://policyengine--policyengine-macro-mcp-serve.modal.run/mcp"

async def call(tool, args=None):
    async with streamablehttp_client(URL, timeout=300) as (read, write, _):
        async with ClientSession(read, write) as session:
            await session.initialize()
            res = await session.call_tool(tool, args or {})
    if res.isError:  # a failed tool or job returns plain text, not JSON
        raise RuntimeError(res.content[0].text)
    return json.loads(res.content[0].text)

forecast = asyncio.run(call("forecast_uk", {"horizons": 4}))
Polling helper for slow tools
add to hosted.py
async def run_job(tool, args):
    """Slow tools: start a job, then poll until it is done."""
    job = await call("start_job", {"tool": tool, "arguments": args})
    while True:
        r = await call("get_job_result", {"job_id": job["job_id"], "wait_seconds": 30})
        if r["status"] == "done":
            return r["result"]

score = asyncio.run(run_job("score_reform", {
    "country": "uk", "model": "obr",
    "reform": {"gov.hmrc.income_tax.rates.uk[0].rate": 0.21},
    "years": 2,  # each scored year adds a microsimulation run; 2 keeps the job short
}))

Notes on incidence and local models
  • Incidence tools (*_incidence) are experimental: a macro path laid onto households, not a reform score.
  • DEFINE-UK scenarios are never hosted (the upstream is unlicensed): hosted calls return run instructions, and the incidence tool runs hosted on a locally produced define_payload. pip install git+https://github.com/PolicyEngine/define-uk-model fetches the pinned upstream at runtime; scenario deltas come from a cached local run, and a fresh one needs local R.
  • OG-UK + microsimulation is experimental and UK only: an OG-UK steady-state solve feeds long-run wage changes back into a second microsimulation run. Until OG-UK#68 the solve needs its own environment: run pe-macro og-score --reform '{"gov.hmrc.income_tax.rates.uk[0].rate":0.21}' --json > og.json there, then pe-macro dynamic-score --reform '{"gov.hmrc.income_tax.rates.uk[0].rate":0.21}' --og-payload og.json; both steps need the same --reform.
  • Tool names are a fixed contract (tool_surface.py), so renaming one is a reviewed, breaking change.

Limits and cold starts

Free, with a spend cap.

150 srequest ceiling

Longer calls run as 30-minute jobs.

3containers at once

Scales to zero when idle.

5 minwarm after the last request

Cold: ~20 s import; UK forecast: minutes.

Limits in detail
  • The hosting transport drops any request after 150 seconds. start_job hands a slow call to a worker with a 30-minute budget and returns a job id; poll get_job_result. score_reform always runs as a job; obr_shock, frbus_shock, hank_shock and a cold population run (pe_population_impact) when cold. Locally, call the tool directly.
  • get_job_result blocks at most 60 seconds per call; keep polls short. A poll that errors is not a failed job: call again with the same id. Job names are the adapter names: score_reform, obr_shock, frbus_shock, hank_shock, pe_population_impact, dynamic_population_reform_impact.
  • A container stays warm five minutes after the last request. In a fresh one the first PolicyEngine call pays a ~20 s import and the first UK forecast a couple of minutes of estimation.
  • Only a local UK population or reform score needs HUGGING_FACE_TOKEN (private policyengine-uk-data-private).
  • Local only: model='og', dynamic_reform_impact (tens of minutes) and the DEFINE-UK scenarios. Called hosted they return run instructions or an import error.
  • Every score_reform result carries a score block: model class, horizon, provenance, units and time basis, assumptions, caveats and a comparability label. Scores from different model classes are complementary: never average or rank them.
