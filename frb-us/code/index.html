Overview Methodology Validation Use it

Ask the server, or install it

Five steps, from a hosted one-liner to the full model in Python.

1

Ask the hosted server

The hosted MCP server has three tools: frbus_list_variables (the shockable levers, with units), frbus_shock (solve and return impulse responses), and frbus_summary (vintage and validation provenance).

pe-macro frbus-variables
pe-macro frbus-shock --var rffintay_aerr --shock 1.0
pe-macro frbus-summary
About this step

The same three on the CLI

The CLI runs them locally, with no server round-trip.

2

Two traps

Units differ by lever. rffintay_aerr is in percentage points (1.0 = a 100bp tightening); spending levers such as egfe_aerr are in log points of quarterly growth, not billions of dollars. A dollar-sized number diverges the solver.

About this step

Each rule reads its own add-error. rffintay_aerr works only under inertial_taylor; taylor rejects it and points to rfftay_aerr.

The rejection replaces what would otherwise be silent all-zero responses.

3

Choose the policy rule

frbus_shock takes a policy_rule: inertial_taylor (the default, the LONGBASE rule, used by the validation numbers), taylor (the non-inertial variant), or fixed_funds_rate, which holds the funds rate on its baseline path, so there is no endogenous monetary offset.

About this step

The rule is usually the point of the exercise: a four-quarter federal-purchases shock of 0.01 log points peaks higher on real GDP with the funds rate fixed, and the price-level response is larger still.

4

Install the package

Install for the full 284-variable model, the Board's own demo scripts, or anything the three tools do not expose. The package is separate from the rest of the suite, with its own Python API.

git clone https://github.com/PolicyEngine/us-frb-model
cd us-frb-model
uv venv && uv pip install -e ".[dev]"
About this step

The Board's raw materials are vendored unmodified, so there is no data download, but you clone rather than pip-install from an index.

5

Run a 100bp shock in Python

Load LONGBASE, set the Board's demo fiscal configuration, add-factor with init_trac so the baseline reproduces LONGBASE exactly, add the shock, solve.

import pandas as pd
from frbus import Frbus, load_data

data = load_data("vendor/data_only_package/LONGBASE.TXT")
model = Frbus("vendor/pyfrbus_package/models/model.xml")

start, end = pd.Period("2026Q1"), pd.Period("2030Q4")

# the fiscal-policy configuration the Board's own demos use
data.loc[start:end, "dfpdbt"] = 0
data.loc[start:end, "dfpsrp"] = 1

# add-factor the model so the baseline reproduces LONGBASE exactly
with_adds = model.init_trac(start, end, data)

# 100bp monetary policy shock in the first quarter
with_adds.loc[start, "rffintay_aerr"] += 1
sim = model.solve(start, end, with_adds)

print((sim.loc[start:end, "xgdp"] / with_adds.loc[start:end, "xgdp"] - 1) * 100)
